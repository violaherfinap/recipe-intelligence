## 5. Split Train/Test 65/50

### Spesifikasi

115 query beku dibagi menjadi **65 train** dan **50 test** pada level query.

| Slice | Total | Train | Test |
| --- | ---: | ---: | ---: |
| `easy` | 35 | 20 | 15 |
| `multi-hop` | 25 | 14 | 11 |
| `temporal` | 30 | 17 | 13 |
| `no-evidence` | 25 | 14 | 11 |
| **Total** | **115** | **65** | **50** |

Metode:

- Query dihubungkan menjadi komponen jika berbagi gold document `relevance=2`.
- 104 gold document, 35 dipakai lebih dari satu query -> **88 komponen** (terbesar 5 query).
- Seluruh komponen masuk satu sisi; assignment diselesaikan dengan DP exact-cover dan seed 42.
- Hasil: **54 gold document di train, 50 di test, 0 overlap**. Komponen yang mencakup lebih dari satu slice: 8.
- File query asli tidak diubah; split hanya menambah file turunan.

### Aturan

1. Train hanya untuk kalibrasi threshold NLI, tau sufficiency, dan pemilihan konfigurasi.
2. Test hanya untuk angka final setelah `w3-config-frozen`.
3. Jangan memilih parameter atau split berdasarkan performa model di test-50.
4. Gold passage milik 65 query train tetap `split=test` di korpus. Karena itu passage tersebut **tidak boleh** dipakai sebagai teks training LoRA atau few-shot example.
5. Query, qrels, dan hash test tidak berubah; split disimpan di file terpisah dan tidak menggantikan `benchmark/queries.jsonl`.

### Path

- `benchmark/query_split.json` (peta split + metadata)
- `benchmark/queries_train.jsonl` (65)
- `benchmark/queries_test.jsonl` (50)
- `benchmark/queries.jsonl` (115; sumber beku, tidak diubah)

Reproduksi:

```powershell
uv run python tools/split_queries.py
uv run pytest tests/unit/test_query_split.py -q
```
